Client Gallery Setup

This page walks through connecting real Google Sign-In and a live Google Sheet client list to your site — once set up, adding new clients never requires touching code again.

1 Create a free Google OAuth Client ID

This lets clients sign in with their real Google account on login.html. One-time setup, takes a few minutes.

  1. Go to console.cloud.google.com and create a new project (any name works).
  2. Go to APIs & Services → OAuth consent screen, choose "External," and fill in your studio name and logo.
  3. Go to APIs & Services → Credentials → Create Credentials → OAuth Client ID, choose "Web application."
  4. Under Authorized JavaScript origins, add the URL your site will live at (e.g. https://yourdomain.com).
  5. Copy the Client ID it generates — it ends in .apps.googleusercontent.com.

2 Add the Client ID to your site

Open login.html, find this line near the bottom of the file, and paste your Client ID in:

const GOOGLE_CLIENT_ID = 'YOUR_GOOGLE_CLIENT_ID.apps.googleusercontent.com';

3 One-time: connect a Google Sheet as your client list

This is what lets you add new clients later without ever touching code again.

  1. Make a new Google Sheet with seven column headers in row 1: Name, Email, FolderId, Passcode, ExpiresOn, CoverPhotoId, IntroVideoUrl
  2. In the sheet, go to File → Share → Publish to web
  3. Choose the correct sheet tab, set format to Comma-separated values (.csv), click Publish
  4. Copy the URL it gives you
  5. Open gallery.html, find SHEET_CSV_URL near the top of the script, and paste your URL in
  6. Do the same in login.html — find SHEET_CSV_URL_LOGIN and paste the same URL in

That's it — this only needs to be done once, ever.

4 For each new couple, from now on

  1. Create a Google Drive folder and upload their photos.
  2. Right-click the folder → Share → set access to "Restricted" → add their exact Google account email.
  3. Open the folder and copy the ID from the URL: drive.google.com/drive/folders/THIS_PART
  4. Add one new row to your Google Sheet with their name, email, and folder ID. Use the generator below if it's easier to build the row first.

No redeploying, no code editing — the website reads the sheet live every time someone logs in.

Why this is still secure: the gallery link opens the couple's actual Drive folder in a new tab, not embedded in this site. That means Google Drive's own "Restricted" sharing genuinely applies — if someone's Google account wasn't shared on that folder, Drive itself will deny them, even if they somehow saw the folder ID. Your site's login and sheet just get the right couple to the right link; Drive does the actual guarding.

5 Optional: one shared code for family & guests

Individual Google accounts work well for the couple themselves, but asking every parent, sibling, and relative to have their exact email added to Drive isn't realistic. For them, use a shared passcode instead — one code, handed out however the couple likes (text message, printed card, WhatsApp group).

  1. Change that couple's Drive folder sharing from "Restricted" to "Anyone with the link" (view only). This is the trade-off: the passcode becomes the real gatekeeper instead of Drive's per-email check.
  2. In your Google Sheet, fill in the Passcode column for that row with a short code, e.g. MAYA2026.
  3. Share the passcode with the couple, and let them pass it on to whoever they want to have access.

Good for: letting a wedding party of 20 relatives in without 20 separate Google account invites. Worth knowing: anyone with the code can get in, and anyone with the code could technically pass it along further — treat it like a shared house key, not a bank password. If a couple wants tighter control, stick to individual email invites for them instead.

Two easy ways to reduce the risk without losing the convenience: use the Generate button below instead of a guessable name+year code, so nobody could stumble onto another couple's gallery by luck — and set an expiry date (e.g. 60 days after delivery) so an old code stops working on its own instead of staying open forever.

6 Optional: show real photos in a premium in-page gallery

Without this step, clients see a button that opens their album in Google Drive itself — functional, but it looks and feels like Drive, not like your site. This step pulls the actual photos into gallery.html's own styled grid and lightbox instead.

  1. In Google Cloud Console (the same project as your OAuth Client ID), go to APIs & Services → Library, search for "Google Drive API", and click Enable.
  2. Go to APIs & Services → Credentials → Create Credentials → API Key. Copy the key it generates.
  3. Click Restrict Key on that new key: under "API restrictions," limit it to Google Drive API only. Under "Application restrictions," choose "Websites" and add your domain. This stops anyone else from using your key elsewhere.
  4. Open gallery.html, find DRIVE_API_KEY near the top of the script, and paste your key in.

Important: this only works for folders shared as "Anyone with the link" (the same setting used for the family passcode option above) — the API key can't read a "Restricted" folder. If a couple's folder is still Restricted, their gallery will automatically fall back to the plain "Open in Drive" button instead, so nothing breaks either way.

If you skip this step entirely, everything still works — galleries just open in Drive directly rather than showing inline.

7 Optional: a welcome moment before the gallery (photo or video)

Show a full-screen cover photo or short video the moment a client logs in, before they see the grid — a nice "your gallery is ready" moment. Entirely optional and set per couple.

  1. For a cover photo: pick any photo already in their Drive folder, get its file ID the same way you got the folder ID, and put it in the CoverPhotoId column.
  2. For a video instead (takes priority over the photo if both are set): put a link in the IntroVideoUrl column. This accepts a YouTube link, a Vimeo link, a Drive video file's share link, or a direct .mp4 URL.
  3. Leave both blank for couples who don't need this — their gallery just loads straight to the grid as normal.

The overlay shows once per login session (not every time someone clicks around the gallery) and has a "View Gallery" button to dismiss it.
